How to download Looperman loops with Python

You need an account and a logged-in session. The MP3 preview on a listing page is public; the WAV comes from a /getfiles/ link that only exists for a logged-in visitor, and every download counts against a per-account quota. LoopHaven opens that session on your own machine and streams the resulting file.

Verified against the live site on 16 November 2026 · LoopHaven 0.1.0

The preview is enough to audition material and decide. The WAV is what you actually load into a DAW, and it is the part that has rules attached.

The symptom that wastes a day: zero download links

A loop's detail page contains 16 links to /getfiles/ when you are logged in — the loop itself plus every recommended loop rendered below it. Fetched without a session, the same page contains zero.

So when a scraper reports “no download link on the page”, the cause is almost never a markup change or a quota. It is an expired cookie. The three symptoms — health check says logged in, download button appears, download fails — are one wrong predicate. Checking a session properly is worth reading before you debug anything else.

Working flow

python -m uvicorn loophaven.api.app:app --host 127.0.0.1 --port 8000

# open a session (prompts locally; the password is never stored)

Search, then fetch, in Python

import pathlib, re, requests

BASE = "http://127.0.0.1:8000"

found = requests.get(f"{BASE}/api/search", params={
    "genre": "Trap", "bpm": 140, "key": "Cm", "limit": 3,
}, timeout=30).json()

for item in found["loops"]:
    print(item["id"], item["bpm"], item["key"], item["title"])

loop_id = found["loops"][0]["id"]

info = requests.get(f"{BASE}/api/download/info/loop/{loop_id}", timeout=30).json()
if not info["download_available"]:
    raise SystemExit(f"not available (logged_in={info['logged_in']})")

audio = requests.get(f"{BASE}/api/download/audio/loop/{loop_id}", timeout=120)
audio.raise_for_status()

stem = re.sub(r"[^A-Za-z0-9 ._-]+", "_", info["title"]).strip()
out = pathlib.Path("loops")
out.mkdir(exist_ok=True)
path = out / f"{stem}.{info['expected_format']}"
path.write_bytes(audio.content)
print(info["size_hint"], "->", path)

Check the headers before you trust the file

A download that silently succeeds is the failure mode worth guarding against: a quota page or a login page returned with 200 would otherwise be saved as .wav and break later, in the DAW, with no trace of where it came from.

HTTP 200
Content-Type: audio/wav
X-Audio-Format: wav
Content-Disposition: attachment; filename="looperman-l-8513679-0436799-....wav"
  • Content-Type is the real type, not a guess from the URL.
  • X-Audio-Format is wav for loops and mp3 for acapellas — acapellas have no WAV, whatever you ask for.
  • 429 is Looperman's quota, passed through unchanged.
  • 502 means the upstream answered with HTML instead of audio. Nothing is written to disk.
  • 401 means no session is open.

Several loops at once

POST /api/download/zip builds a personal pack of 2–4 loops, with a README.txt recalling the licence situation. Any file that fails is written into the ZIP as ERROR_<id>.txt with the reason, rather than silently substituted with a different format.

curl -X POST "http://127.0.0.1:8000/api/download/zip" \
  -H "Content-Type: application/json" \
  -d '{"ids": ["434657", "434373"], "format": "wav", "filename": "pack.zip"}' \
  -o pack.zip

Four loops is the practical ceiling because the quota is per account. This is a sampling tool, not a mirroring tool.
