Looperman search filters: the complete reference

Looperman's advanced search exposes 69 genres, 40 categories, 24 keys, 4 time signatures and 10 sort orders. Every value below was read from the site's own form, not guessed from a URL. Two of them surprise people: tempo is a range (ftempo and ttempo), and flats are not stored at all — Bb is written am.

Tempo is a range, not a value

There is no bpm= parameter upstream. A tempo is expressed as a lower and an upper bound, and an exact tempo is simply the same number twice: ftempo=140&ttempo=140. LoopHaven accepts bpm=140 as a shortcut; ftempo=90&ttempo=110 searches the band between them.

Keys: there are no flats

Sharps are written with an s, and a minor key appends m: fs is F#, fsm is F#m. Flat spellings do not exist, because the pitch classes are stored as sharps — which is why Bb appears as am and Eb as dsm.

A wrapper that forwards bb unchanged does not get an error. It gets an unfiltered page, which looks like a working search until someone notices the keys are all wrong. Sending Bb to LoopHaven is safe: it translates before the request.

Acapellas have their own filters

Acapella search accepts a different set. Passing a loops-only filter such as category to it is a mistake worth catching early: the site ignores cid= on that listing and still returns results, so the filter looks like it works. LoopHaven rejects it with 422.

The one filter that does nothing

Loop cards display the DAW a loop was made in, and the site has a did parameter for it, so it looks filterable. It is not: searching with did returns results that ignore it. Nothing in the page signals this, which is why it reads as a broken parser for a week before anyone checks the form.

Using them

Labels, numeric ids and slugs are all accepted, and the response echoes what was resolved:

curl "http://127.0.0.1:8000/api/search?genre=Phonk&category=Drum&key=F%23m&ftempo=140&ttempo=145&when=2&order=downloads&dir=d"

{
  "resolved": {
    "genre": { "id": 70, "label": "Phonk" },
    "category": { "id": 1, "label": "Drum" },
    "key": { "id": "fsm", "label": "F#m" }
  }
}

An unknown value returns 422 with suggestions, rather than an empty page that is indistinguishable from “nothing matches”.
